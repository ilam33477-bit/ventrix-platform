# Контракт первого подключения и initial sync

## Пользовательский поток

Все экраны клиентского бота inline-first и редактируют одно сообщение:

1. информированное согласие и инструкция создать рабочую папку;
2. телефон → одноразовый код → optional 2FA;
3. каталог папок и диалогов;
4. рабочая папка;
5. отдельное согласие на предварительную проверку личных диалогов;
6. период 3/7/14/30 дней, по умолчанию рекомендуется 7;
7. live progress, остановка, итоговые метрики;
8. ручное включение или исключение личных диалогов с низкой уверенностью.

Код и 2FA удаляются из чата, не записываются в FSM/БД и не попадают в логи. Телефон, code hash, pending session и постоянная StringSession хранятся только как Fernet ciphertext; временные секреты помечаются удалёнными сразу после успешной авторизации.

## Исполнение

Каждый выбранный диалог получает `TelegramSyncCursor` и durable job. Worker читает историю небольшими batch, сохраняет offset и число сообщений, ставит следующую порцию с idempotency key и выдерживает паузу. `FloodWait` задаёт фактический retry delay. Ошибка одного диалога фиксируется в его cursor и не останавливает остальные.

Файлы не скачиваются: сохраняются только тип, имя, MIME type и размер. Уникальные ограничения на remote message и problem fingerprint защищают от дублей. После рестарта pending/retry jobs, cursors и координаты progress message остаются в SQLite.

## Личные диалоги

Без явного согласия личные диалоги не получают sync jobs. После согласия они загружаются для предварительной классификации по контексту последних сообщений. Диалог с низкой уверенностью получает `requires_user_confirmation=true` и не создаёт operational problems, пока владелец явно не подтвердит его как рабочий. Название и username сами по себе не считаются достаточным сигналом.

## Удаление

«Отключить» пытается завершить remote Telegram authorization и в любом случае удаляет локальный ключ сессии. «Удалить загруженные данные» после отдельного подтверждения отменяет ожидающие sync jobs и безвозвратно удаляет сообщения, cursors, runs, проблемы, каталог и все tenant Telegram secrets.

## Mini App

`GET /api/v1/client/bootstrap` принимает `Authorization: tma <Telegram.WebApp.initData>`, проверяет HMAC-SHA-256 и свежесть `auth_date`, затем возвращает только tenant-scoped состояние. Меню зависит от этапа: до подключения, выбор, синхронизация, готовность, ошибка/повторная авторизация.
