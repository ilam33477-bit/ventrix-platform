# Telegram UI contract: inline-first

Административный и клиентские боты используют единый inline-first подход.

## Обязательные правила

- Постоянные `ReplyKeyboardMarkup` запрещены. После обновления `/start` удаляет старую reply-клавиатуру.
- Навигация выполняется только через `InlineKeyboardMarkup` и callback data.
- Один экран представляет одну задачу. Переходы по возможности редактируют текущее сообщение через `edit_text`, а не создают цепочку новых сообщений.
- Каждый вложенный экран имеет кнопку возврата в главное меню или родительскую карточку.
- Текстовые сообщения принимаются только внутри явно активного FSM-state.
- Во время активного FSM несвязанные callback-действия блокируются `ActiveFlowGuardMiddleware`.
- Любая форма имеет «Отменить действие» и «Начать заново». Отмена полностью очищает state и временные данные.
- Секретные сообщения удаляются сразу после чтения, когда Telegram это позволяет.
- Token, код авторизации, пароль, session string и URL Telegram API с token не выводятся в UI или логи.

## Административный бот

Главное меню: клиенты, создание клиента, клиентские боты, активность, состояние и настройки. AI-настройки открываются из карточки клиента.

Создание клиента сохраняет данные только после отдельного экрана проверки и нажатия «Подтвердить». Новый сценарий нельзя запустить, пока текущий не завершён или не отменён.

## Клиентский бот

Главное меню: сводка, важное, отчёты, подключения, панель и настройки. Бот не показывает владельца платформы, внутреннюю архитектуру, поддержку, публичные цены или тарифы.

Подробная аналитика относится к Mini App; бот остаётся поверхностью для коротких сводок, уведомлений и быстрых действий.
